Vaka 0.2.0 is the agent-era release: everything an agent needs to go from "something broke" to a fix PR, plus performance tracing, product analytics, feature flags and OpenTelemetry ingestion.

## Highlights

- **Fix context for agents.** Code mappings turn stack frames into repository source links pinned to the release's commit. `vaka releases set-commits` records commits per release, issues list `suspect_commits` and owners (CODEOWNERS-like ownership rules), and a `Fixes WEB-12` trailer resolves an issue in that release. The new `get_fix_context` MCP tool returns all of it in one call, with a suggested branch name and trailer; `link_issue` records the fix PR.
- **Webhooks and agent triggers.** Alert rules can call webhooks, Slack, email, GitHub `repository_dispatch` or open a GitHub issue on new issues, regressions, spikes, thresholds, resolves, assignments, comments and new releases. Deliveries are logged, retried and can be redelivered.
- **Session timelines and crash precursors.** `get_session_timeline` shows a session in order (pageviews, screens, events, breadcrumbs, errors); `issue_precursors` shows what users did before a crash, with lift versus all sessions.
- **Performance tracing.** Spans and traces from the JS and Rust SDKs: latency percentiles per transaction, slow endpoints, span breakdowns, app start times, Web Vitals (LCP, INP, CLS, FCP, TTFB) and p95 regressions between releases.
- **Product analytics.** Funnels, retention, paths, event catalog, identified users and user timelines; behavioral cohorts usable in any filter; stickiness (DAU/WAU/MAU) and lifecycle; goals, revenue, real-time visitors and release adoption.
- **Feature flags and experiments.** Flags with rollouts and targeting, evaluated at `/ingest/v1/flags` (JS SDK: `flags: true`), flag health (crash-free sessions per variant) and experiments with uplift, confidence interval and p-value.
- **Anomaly detection and digests.** `detect_anomalies` compares errors, crash rate, traffic, events, latency and Web Vitals with the same window in earlier weeks. Daily or weekly digests in any IANA time zone, with an optional narrative paragraph written by any OpenAI-compatible LLM (`VAKA_LLM_BASE_URL`, `VAKA_LLM_MODEL`, `VAKA_LLM_API_KEY`); without one, a template is used. The payload's `narrative_source` says which (`llm` or `template`).
- **OpenTelemetry ingestion.** OTLP/HTTP traces and logs (protobuf or JSON) at `/ingest/otlp/v1/traces` and `/ingest/otlp/v1/logs`, searchable with `search_logs` and joined into traces.
- **Mobile.** The Android SDK detects ANRs and captures native (NDK) crashes; the iOS SDK detects app hangs. Release health reports ANR and hang rates per release.
- **Also:** admin UI login with a one-time email code, S3-compatible storage for debug files (`VAKA_S3_*`), `vaka-bundler-plugin` for uploading source maps from Vite, Rollup and webpack, and a Fly.io deploy config.

The MCP server now has around 70 tools; see `docs/mcp.md`.

## Upgrading

Database migrations (002 to 009) and the new ClickHouse tables are applied automatically on start. There are no breaking API changes from 0.1.0.

## Install

Server (multi-arch image, amd64 and arm64):

```sh
docker pull ghcr.io/erikhellman/vaka:0.2.0
```

iOS (Swift Package Manager):

```swift
.package(url: "https://github.com/ErikHellman/vaka", from: "0.2.0")
```

JavaScript: `<script defer src="https://<your-vaka>/sdk/vaka.js" ...>` from your instance. The `vaka` CLI binaries for Linux (x86_64, aarch64), macOS (Apple silicon) and Windows (x86_64) are attached below.

Docs: https://vaka.hellsoft.se (also served by every instance at `/docs/` and `/llms.txt`).

## Known gaps

- **Android SDK and Gradle plugin are not on Maven Central yet.** Include them from source with `includeBuild("../vaka/sdks/android")` (see `docs/install/android.md`).
- **npm:** published on 2026-11-14 as `@hellsoft/vaka-browser`, `@hellsoft/vaka-bundler-plugin` and `@hellsoft/vaka-node` (the unscoped names were taken).
