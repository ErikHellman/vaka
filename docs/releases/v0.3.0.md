Vaka 0.3.0 adds user feedback across every platform and a backend SDK for most server languages: Node.js, Python, Go, JVM and .NET join Rust.

## Highlights

- **User feedback.** Users can send feedback with an optional email, screenshots and a link to the error they just hit. The browser SDK has an embeddable widget, Android and iOS/macOS/tvOS have native forms, and every SDK can offer a feedback prompt after a crash or hang. Backends can forward their users' feedback with `captureFeedback` (Node, Python, Go, Rust, JVM, .NET), optionally linked to an issue. Agents read it with the new MCP tools `list_feedback`, `get_feedback` (screenshots come back as images), `feedback_summary` and `update_feedback`, and alert rules can trigger on new feedback. See `docs/feedback.md`.
- **New backend SDKs.**
  - Node.js: `@hellsoft/vaka-node` (errors, sessions, flags, OpenTelemetry traces; Node 22.15+).
  - Python: `vaka-sdk` on PyPI (Django, Flask, FastAPI, logging, optional OpenTelemetry; Python 3.9+).
  - Go: `github.com/ErikHellman/vaka/sdks/go`, on top of OpenTelemetry.
  - JVM: `se.hellsoft.vaka:vaka-jvm` for Java, Kotlin and Scala, on top of OpenTelemetry.
  - .NET: `Vaka`, `Vaka.OpenTelemetry` and `Vaka.AspNetCore`.
- **npm packages renamed** to the `@hellsoft` scope: `@hellsoft/vaka-browser`, `@hellsoft/vaka-bundler-plugin` and `@hellsoft/vaka-node`.
- **Rust SDK on crates.io** as `vaka-sdk`.
- **Reusable deployments.** Docker Compose is driven by `.env` (`VAKA_VERSION` pins the image) and the Fly.io config is templated.

## Security

- `X-Forwarded-For` and `X-Real-IP` are now only believed when the connecting peer is a trusted proxy (`VAKA_TRUSTED_PROXIES`, default: loopback and private ranges). Before, any caller could pick its own address, dodging per-address limits and skewing visitor counts. If your reverse proxy or a backend that forwards feedback connects from a public address, add it to `VAKA_TRUSTED_PROXIES`.

## Upgrading

Migration 010 (feedback) is applied automatically on start. There are no breaking API changes from 0.2.0. Check `VAKA_TRUSTED_PROXIES` if Vaka runs behind a proxy with a public address (see above). If you used the old unscoped npm names from source, switch to the `@hellsoft/*` packages.

## Install

Server (multi-arch image, amd64 and arm64):

```sh
docker pull ghcr.io/erikhellman/vaka:0.3.0
```

SDKs:

| Platform | Package |
| --- | --- |
| Browser | `npm i @hellsoft/vaka-browser` (or `/sdk/vaka.js` from your instance) |
| Node.js | `npm i @hellsoft/vaka-node` |
| Python | `pip install vaka-sdk` |
| Go | `go get github.com/ErikHellman/vaka/sdks/go@v0.3.0` |
| Rust | `vaka-sdk = "0.3"` |
| iOS, macOS, tvOS | `.package(url: "https://github.com/ErikHellman/vaka", from: "0.3.0")` |

The `vaka` CLI binaries for Linux (x86_64, aarch64), macOS (Apple silicon) and Windows (x86_64) are attached below.

Docs: https://vaka.hellsoft.se (also served by every instance at `/docs/` and `/llms.txt`).

## Known gaps

- **Android SDK, Gradle plugin and JVM SDK are not on Maven Central yet** (the `se.hellsoft` namespace is still being verified). Include them from source; see `docs/install/android.md` and `docs/install/jvm.md`.
- **.NET packages are not on NuGet yet.** Build them from `sdks/dotnet` with `dotnet pack` (see `docs/releasing/dotnet.md`).
