Vaka 0.4.0 adds uptime and cron monitoring, SMS alerts and a supported way to move from SQLite to Postgres, and fixes the findings of a backend security review. **Read "Upgrading" before you deploy it: some configuration that 0.3.0 accepted is now refused.**

## Upgrading

Database migration 011 (monitors) runs on start. Check these before you roll out:

- **Passwords need at least 12 characters** and can't be a common placeholder such as `change-me…`. This applies to new and changed passwords, and to `VAKA_ADMIN_PASSWORD` when it creates the first owner (Vaka refuses to start on a fresh database with a weak one). Existing passwords keep working.
- **Docker Compose requires `CLICKHOUSE_PASSWORD`.** Set it in `.env` (for example `openssl rand -hex 24`). Compose now trusts forwarding headers only from the bundled Caddy.
- **Alert targets on private addresses are refused.** Webhook and Slack targets must be public `http(s)` URLs. Redirects are no longer followed. If you alert to an internal host, set `VAKA_ALLOW_PRIVATE_ALERT_TARGETS=true`. Project-scoped tokens can no longer set URL targets, and readers see targets redacted.
- **Set `VAKA_SECRET_KEY`** to encrypt stored alert secrets (webhook signing secrets, GitHub tokens) at rest. Existing plaintext secrets are encrypted on start. Keep the key stable: if it changes, those rules break until their secrets are set again.
- **Default trusted proxies no longer include CGNAT (100.64.0.0/10) or link-local ranges.** If your proxy reaches Vaka from one of them, add it to `VAKA_TRUSTED_PROXIES`.
- **New rate limits.** Ingest is limited per project and per client, and new issues are capped per hour. Logins and email codes are throttled.
- **Sessions end on password change.** Changing a password or disabling a user revokes their sessions. Admins can no longer manage owners or other admins.

There are no breaking changes to the ingest or REST APIs or to the SDKs.

## Highlights

- **Monitoring.** Three kinds of monitor: **heartbeat** (cron jobs and queues check in; missed, failed or slow runs open an incident), **HTTP** (uptime, status code and optional body check) and **TLS** (certificate expiry). Incidents have flap protection and send down/up alerts through any alert channel. Each incident stores a "why is it down?" snapshot: recent releases, the issues that spiked, error rate, error logs and errors from the failed run. New MCP tools: `list_monitors`, `get_monitor`, `create_monitor`, `update_monitor`, `delete_monitor`, `run_monitor_check`, `list_incidents` and `get_incident`. The admin UI has monitor pages. See `docs/monitoring.md`.
- **Heartbeat helpers** in the CLI (`vaka monitor run nightly-backup --cron "0 3 * * *" -- ./backup.sh`), Node, Python (`vaka.check_in`) and Go. Errors captured during a monitored run are tagged with the run.
- **SMS alerts** through 46elks, Twilio or Sinch (`VAKA_SMS_PROVIDER`), with a server-wide daily cap (`VAKA_SMS_MAX_PER_DAY`). See `docs/alerts.md#sms`.
- **SQLite to Postgres.** `vaka-server migrate-db` copies all metadata from a consistent snapshot, resets sequences and checks row counts. Read-only maintenance mode (`PUT /api/v1/admin/read-only` or `VAKA_READ_ONLY`) holds metadata writes during the switch while events keep flowing. See "Moving from SQLite to Postgres" in `docs/self-hosting.md`.

## Security

Fixes from the backend security review:

- SSRF protection for alert targets (see "Upgrading").
- The symbol cache no longer leaks memory. ProGuard and native debug file uploads are validated, and uploads have a per-project quota.
- Crash text put into GitHub issues and dispatches is escaped and marked untrusted. MCP marks tool output that carries end-user data as untrusted and caps JSON-RPC batches.
- Login throttling, a 12-character password minimum, argon2 on a bounded pool, and session revocation.
- Origin checks on cookie-authenticated requests, security headers (CSP, frame-ancestors, Referrer-Policy, HSTS on https), and generic 500 messages with an error id.
- ClickHouse reads run read-only with a time and memory budget. New API tokens and invite links are never put in a URL.
- Fixed: on Postgres, every debug file upload failed (artifact quota sum is now cast to BIGINT).

## Install

Server (multi-arch image, amd64 and arm64):

```sh
docker pull ghcr.io/erikhellman/vaka:0.4.0
```

SDKs:

| Platform | Package |
| --- | --- |
| Browser | `npm i @hellsoft/vaka-browser` (or `/sdk/vaka.js` from your instance) |
| Node.js | `npm i @hellsoft/vaka-node` |
| Python | `pip install vaka-sdk` |
| Go | `go get github.com/ErikHellman/vaka/sdks/go@v0.4.0` |
| Rust | `vaka-sdk = "0.4"` |
| iOS, macOS, tvOS | `.package(url: "https://github.com/ErikHellman/vaka", from: "0.4.0")` |

The `vaka` CLI binaries for Linux (x86_64, aarch64), macOS (Apple silicon) and Windows (x86_64) are attached below.

Docs: https://vaka.hellsoft.se (also served by every instance at `/docs/` and `/llms.txt`).

## Known gaps

- **Android SDK, Gradle plugin and JVM SDK are not on Maven Central yet** (the `se.hellsoft` namespace is still being verified). Include them from source; see `docs/install/android.md` and `docs/install/jvm.md`.
- **.NET packages are not on NuGet yet.** Build them from `sdks/dotnet` with `dotnet pack` (see `docs/releasing/dotnet.md`).
