First public release of Vaka: self-hosted crash reporting and analytics built for coding agents.

## What's in it

- **Server** (`vaka-server`): ingest API, issue grouping, regressions, release health, cookieless web and mobile analytics, server-side symbolication (JS source maps, Android R8/ProGuard, iOS dSYM, Rust/ELF), alerts, REST API at `/api/v1`, MCP server at `/mcp`, and a small admin UI. Metadata in SQLite or Postgres, events in ClickHouse.
- **`vaka` CLI**: debug file and mapping uploads, issue queries, health checks. Binaries for Linux (x86_64, aarch64), macOS (Apple silicon) and Windows (x86_64) are attached below.
- **SDKs**: JavaScript (browser), Android (Kotlin, plus the `se.hellsoft.vaka` Gradle plugin for R8 mappings), iOS (Swift package `Vaka`), Rust, and a documented HTTP ingest API for anything else.

## Install

Server (multi-arch image, amd64 and arm64):

```sh
docker pull ghcr.io/erikhellman/vaka:0.1.0
```

or `cp .env.example .env && docker compose up -d` from this repo. See `docs/self-hosting.md`.

iOS (Swift Package Manager):

```swift
.package(url: "https://github.com/ErikHellman/vaka", from: "0.1.0")
```

JavaScript: load the SDK from your Vaka instance with `<script defer src="https://<your-vaka>/sdk/vaka.js" ...>` (see `docs/install/javascript.md`).

## Known gaps

- **Android SDK is not on Maven Central yet.** Publishing needs a Sonatype account and signing key. Until then, include it from source with `includeBuild("../vaka/sdks/android")` as described in `docs/install/android.md`.
- **`vaka-browser` is not on npm yet.** Use the script tag or `/sdk/vaka.js` served by your instance.
- **The docs site (vaka.hellsoft.se) isn't live yet.** The same docs are in `docs/` and are served by every instance at `/docs/` and `/llms.txt`.
